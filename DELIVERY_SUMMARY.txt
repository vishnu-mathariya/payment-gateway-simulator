FORM VALIDATION:

  • Touched field tracking prevents premature errors
  • Submit button disabled until form valid

  • Auto-format with spaces every 4 digits
  • Detect card type from first digits
  • Smart CVV (3 for regular, 4 for Amex)
  • Live card preview updates in real-time
  • Gradient colors per card type

PAYMENT PROCESSING:
  • Mock gateway with realistic outcomes:
    - 60% success rate
    - 25% failure rate with reasons
    - 15% timeout rate (8-second delay)
  • Proper timeout handling using AbortController
  • 6-second frontend timeout threshold
  • Clean state management for all outcomes

RETRY LOGIC:
  • Maximum 3 retry attempts per transaction
  • Same transaction ID reused across retries
  • Attempt counter displayed to user
  • After 3 failures, retry disabled

TRANSACTION HISTORY:
  • Persists in localStorage
  • Survives page refresh
  • Click to expand for full details
  • Shows ID, amount, status, timestamp
  • Displays failure reasons and attempt count

                         TESTING SCENARIOS

To test the application, follow these scenarios:

TEST 1 - SUCCESSFUL PAYMENT (60% success rate):
  Card: 4242 4242 4242 4242
  Expiry: 12/25
  CVV: 123
  Name: John Doe
  Amount: 100
  Currency: INR
  → Submit and see success screen

TEST 2 - FAILED PAYMENT (25% failure rate):
  Use same card as above
  Submit multiple times until failure
  → Click "Retry" button up to 3 times
  → See specific failure reason

TEST 3 - TIMEOUT PAYMENT (15% timeout rate):
  Use same card as above
  Submit and wait 6+ seconds
  → See timeout message
  → Click "Retry"

TEST 4 - FORM VALIDATION:
  Try entering:
    • Partial card number (< 13 digits)
    • Expired date (earlier than today)
    • Invalid CVV length
    • Empty amount field
  → See appropriate error messages
  → Errors clear when corrected
  → Submit button disabled

TEST 5 - PERSISTENCE:
  Submit successful payment
  Refresh page (Ctrl+R or Cmd+R)
  → Transaction still visible in history
  → Click to expand and see details
